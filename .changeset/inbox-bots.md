Add bots, automations and the tick. `config.bots` now maps each key to a lazily imported class implementing `Bot`, made through the container. The inbox runs a bot's turn after a debounce on each inbound message on a ticket it holds, and when it gets the ticket. A turn computes outside any transaction and commits its replies, its state and an optional handoff (`return`, `transfer` or `close`) in one write guarded by the ticket version it read: dropped when a human took the ticket, run again when a message arrived, and never sent twice. `config.automations` takes `assignOnOpen`, `assignQueuedOnMessage`, `autoReply`, `closeInactive` and your own `defineAutomation`, whose effects are data applied through the ticket state machine. `ticket_opened` and `message_received` automations land in their trigger's write, and `tick` ones run from `inbox.tick()` and the new `node ace inbox:tick` command, which `configure` registers. `inbox.recover()` now queues at most `RECOVER_BATCH` of each kind of lost work per run and marks work older than `GIVE_UP_AFTER_MS` failed, through a new `failed_at` column on `inbox_channel_events` and the `expired` failure code on messages.
