Add the package with its pure core. `defineNode` defines a node type in one object: a VineJS config schema, defaults, ports, per-field bindings, an optional effect, an `upgrade` for older type versions and a `validate` rule. `go`, `set`, `read` and the effect payload are checked against the node at compile time. `defineNodes` builds the registry, with a serializable catalog that carries each config as JSON Schema plus `x-ui` hints, the effects derived from the nodes, and `check` and `compile`. The built-in nodes are `start`, `message`, `question`, `condition`, `set_variable`, `delay`, `handoff`, `close` and `end`. `runTurn` is the interpreter: it takes the stored run state and an `assigned`, `message` or `wake` trigger and returns what to say, the effects, the next state and the handoff, with a step budget per turn. `checkGraph` in the browser-safe `./graph` entry checks a graph in `draft` or `publish` mode. `graphHash` is the publish identity and ignores layout.

It also runs flows. `configure` writes the config, one migration and five models built from the mixins in `./mixins`. The flows bot, registered under one key in the inbox's `config.bots`, picks a flow from the bindings by priority, channel, queue and condition, pins its published version, and commits each turn's replies, handoff, run row and effects in the ticket's transaction. The `inboxFlows` service saves drafts under a revision check, publishes immutable versions after the strict checks, the queue, attendant and close reason checks and `validatePublish`, restores versions, sets bindings (concurrent sets on one flow take turns, so the last one replaces the others'), and starts and stops runs by hand (starts at once on one ticket leave one run and end the others `replaced`). Effects run inside the turn's transaction or from an outbox with an idempotency key and bounded retries. `flows:tick` wakes runs whose wake was lost, ends runs a person took over, expires manual starts and delivers due effects.
